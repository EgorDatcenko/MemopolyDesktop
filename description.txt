Project: Memopoly — Multiplayer Meme-Themed Board Game

Memopoly is a multiplayer turn-based board game built in Java 17 using the LibGDX framework, inspired by Monopoly but themed around internet meme culture and social media platforms. The game is designed for 2–5 players over a local network or VPN (Radmin VPN for testing), with Steam/Epic integration planned for future release. The visual style is pixel art throughout — board, UI elements, cell textures, buttons, and window frames are all custom pixel-art assets.

Architecture
uses a Listen Server model: one player (the host) runs both a game server and a game client on their machine, while other players connect as guests over TCP using the KryoNet networking library. The server is fully authoritative — all game logic, validation, and state changes happen exclusively on the server side. Clients only send action requests (packets) and render whatever state the server broadcasts back. This prevents cheating and desynchronization. The server and all clients communicate via a shared serialization registry (NetworkRegistry) that registers all packet classes with Kryo so they can be transmitted over the network. The server runs under a stateLock object to prevent concurrent modification of game state from multiple player threads simultaneously.

To simplify connection for non-technical users, the host's IP address is encoded into a short alphanumeric room code (e.g. "GU_PEPE-2A_BIGBOB-...") using a custom base-36 encoding with a checksum, implemented in RoomCodeGenerator. The guest enters this room code, the client decodes it back to an IP address, and establishes a TCP connection. This eliminates the need for users to manually type raw IP addresses.

Game Board
The board contains 40 cells arranged in a classic Monopoly-style loop, built statically in BoardData.buildCells(). Cell types include: START (player receives 200 coins when passing), SITUATION (purchasable property), TAX (mandatory payment of 100), REST (safe landing, nothing happens), JAIL (copyright infringement themed, landing is safe), EVENT (draws a random event card), MEME_BATTLE (triggers a mini-game), and MEME_BANK (special investment mechanic). Properties are grouped by social media platforms: Reddit, TikTok, Instagram, X (Twitter), Telegram, Discord, YouTube, and Twitch — with prices ranging from 60 to 400 coins. Each property has a rent value (fee) that defaults to price/5 with a minimum of 10, though the architecture supports explicitly defined rent values per cell.

Turn Flow
Players take turns rolling dice (RollDiceRequest sent to server), the server calculates movement, checks if the player passed Start (awards 200 coins if so, and applies 10% Meme Bank interest to all players with active deposits at that moment), then calls handleCellLanding() which branches based on cell type. If the cell is a free SITUATION cell, the phase switches to PLAYER_ACTION so the player can choose to buy or decline. If it is owned by another player and not mortgaged, rent is automatically collected. TAX cells deduct 100 coins immediately. EVENT cells draw a random card and apply its effect. The turn ends only when the player explicitly presses the End Turn button (END_TURN action), except in cases of bankruptcy or tax where the turn advances automatically.

Economy
Players start with 1500 coins. Properties can be purchased, mortgaged (for half the price), and bought back (for half the price). When a player cannot afford a payment — checked via maxAffordable which includes potential mortgage value of all owned properties — they go bankrupt: all their properties are released back to the market and they are skipped in turn rotation. When a free property is declined for purchase, it goes to auction: a 30-second timer-based auction runs via ScheduledExecutorService, players place bids in ascending order, and the highest bidder wins. The auction timer resets each time a bid is placed.

Meme Bank
Two cells on the board (indices 22 and 38) are Meme Bank cells. When a player lands on one, the game enters MEME_BANK_ACTION phase exclusively for that player. If the player has no active deposit, they can deposit up to 500 coins. If they have an existing deposit, they can withdraw the full balance or extend it. When any player passes the Start cell, all players with active Meme Bank deposits receive 10% interest on their balance. A special event card (Market Crash / Financial Crisis) zeroes out the landing player's Meme Bank balance entirely.

Meme Battle
The MEME_BATTLE cell triggers a mini-game. The player who lands on it becomes the organizer. All other players receive an invitation with a timer to accept or decline. Players who accept pay a stake; declined players only participate in voting. Once all invitations are resolved, a 60-second collecting phase begins where all participants submit one meme from their hand. After all memes are submitted (or the timer expires), a 30-second voting phase begins where each player votes for someone else's meme (self-voting is blocked). Votes are counted by countVotes() in BattleManager: if one meme has the most votes, its owner wins the full battle bank; if multiple memes tie, a re-vote is held on only those tied memes; if all votes are equal or zero, a draw is declared. In a draw, the organizer receives half the bank and the rest is split among other participants. Non-winning participants receive 10 coins per vote received on their meme as a consolation bonus. The BattleManager class handles all phases using daemon threads with manual timers, early-exit detection (when all players submit/vote before the timer), and an isInBattle flag for loop continuation.

Server Decomposition
The GameServer has been refactored from a monolithic ~750-line class into a layered architecture. Guard classes (TurnGuard, PhaseGuard, AuctionGuard) handle validation — TurnGuard checks whether it's the player's turn, PhaseGuard checks whether the current game phase allows a given action, and AuctionGuard checks auction-specific conditions. Action Handler classes (BuyCellActionHandler, PassBuyActionHandler, MortgageCellActionHandler, BuyBackCellActionHandler, MemeBankActionHandler) each implement a GameActionHandler interface and encapsulate the logic for one specific player action. The GameServer orchestrates these handlers but no longer contains all logic inline in a single switch statement.

Client and UI
The client is built on LibGDX's Screen system with a custom ScreenManager (push/pop/set stack). All screens extend BaseScreen. The UI is built entirely using Scene2D tables and VisUI widgets (VisLabel, VisTextField, VisTextButton, ImageButton, ScrollPane, Dialog). The game screen (GameScreen) contains: a left sidebar with the player's meme hand and chat, a right sidebar with player list, owned cells, and action buttons, board overlay panels (dice, current cell info, feed/log), modal windows for buy/auction/Meme Bank actions (using pixel-art window textures as backgrounds), and a full-screen battle overlay that transitions through INVITE → COLLECTING → VOTING → RESULTS phases. The board itself is rendered by BoardRenderer using a static map.png image with dynamically drawn overlays on top via ShapeRenderer (ownership highlights using colored outline textures per player, mortgage darkening, player tokens as colored circles with drop shadows). Cell positions are stored as relative coordinates in a CELL_LAYOUT float array calibrated to match the pixel-art board image exactly.

The game supports Russian and English localization via LanguageManager (stored in LibGDX Preferences) and TexturePathResolver which maps texture filenames to language-specific folders (screen_ui_ru/ or screen_ui_en/ and gamescreen_ui_ru/ or gamescreen_ui_en/). Players can also select custom meme decks via DeckRepository, which loads .json deck files from the local filesystem.

Notifications and Events
GameState carries a notificationText field and a notificationTimestamp; the client shows a centered pixel-art notification window that auto-dismisses after 3 seconds. Event cards (EventCard) have typed effects: receive money, pay money, skip turn, collect from all players, draw a meme card, and Market Crash (zeroes Meme Bank balance). An EventDeck class provides random card drawing, with planned weighted randomness so rare destructive events like Market Crash appear less frequently.
